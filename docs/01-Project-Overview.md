# RideX B2C — Project Overview

## 1. Vision

Build a reliable, location-aware mobility platform where riders can request transportation, drivers can accept and complete trips, and RideX operations can safely manage the marketplace.

RideX should not be a clone. The foundation should match proven ride-hailing patterns while the product layer introduces measurable differentiators.

## 2. Primary users

### Rider
Requests rides, tracks drivers, pays, rates trips, manages profile and support.

### Driver
Completes onboarding, manages availability, receives offers, performs trips, views earnings and payouts.

### Operations/Admin
Manages drivers, riders, trips, pricing, disputes, safety, payments, promotions and platform configuration.

### Support Agent
Handles support cases without unrestricted administrative privileges.

## 3. Core lifecycle

Rider:
REGISTER → VERIFY → LOGIN → SETUP PROFILE → REQUEST RIDE → MATCHING → DRIVER ACCEPTED → DRIVER ARRIVING → TRIP STARTED → TRIP COMPLETED → PAYMENT → RATING

Driver:
REGISTER → VERIFY → KYC/PROFILE → VEHICLE APPROVAL → GO ONLINE → RECEIVE OFFER → ACCEPT → ARRIVE → START → COMPLETE → EARNINGS → PAYOUT

## 4. Product pillars

- Fast matching
- Transparent pricing
- Driver earnings transparency
- Rider safety
- Reliable location tracking
- Strong payment reconciliation
- Excellent cancellation handling
- Operational visibility
- Fraud prevention
- Extensible mobility platform

## 5. Out of scope for MVP

- Multi-tenant SaaS
- White-label apps
- Complex corporate accounts
- International tax engines
- Autonomous dispatch optimization
- Multi-country compliance
- Full marketplace for third-party mobility providers

These can be introduced later if the product proves the need.
